# Blue Leaf Ice Company — concept redesign

A seven-page website concept for **Blue Leaf Ice Company**, an ice supplier in
Edenvale, Gauteng. Built by [Phuture Digital](https://www.phuturedigital.co.za).

> ⚠️ **Blue Leaf Ice Company is a real, trading business.** This is not their
> website, it was not commissioned, and it is not affiliated with or endorsed by
> them. Their real site is `blueleafice.co.za`. Read `CONTENT-NOTES.md` before
> changing a single line of the disclaimer copy.

Live at **https://blueleaf-concept.phuturedigital.co.za**

## What the redesign is actually arguing

Blue Leaf's live site is a one-page Webflow template. Its content is good — the
prices are honest, the zones are sensible, the FAQ answers real questions. The
problem is *where that content lives*:

| On their site | On this concept |
|---|---|
| WhatsApp number **inside a PNG** — untappable on a phone | `tel:` and `wa.me` links in persistent nav chrome |
| Delivery zones, suburbs and fees **inside a PNG** | A real, crawlable, screen-readable table with a suburb lookup |
| Four price tiers as flat text in one long page | Structured tables that a bulk calculator reads directly |
| One page, two anchors | Seven pages, so "ice delivery Bedfordview" has somewhere to land |
| Hero imagery generated by ChatGPT | Photographs of a real ice facility, evidencing the food-grade claim |
| Favicon is a WhatsApp screenshot JPEG | The mark redrawn as vector, legible at 16px |
| Logo is a Didone serif; site is set in a grotesque | Display type matches the logo; body keeps their Instrument Sans |

Nothing about the business was invented. Every fact came from their own
published material — see `CONTENT-NOTES.md`.

## Stack

Plain static HTML, one stylesheet, one script. No framework, no build for the
deployed artefact, no dependencies at runtime. Vercel serves the repo directly.

```
index.html … contact.html   generated pages (committed)
styles.css                  one stylesheet
site.js                     nav, reveal, zone finder, calculator, inert forms
assets/                     18 webp photos + mark.svg + favicon.svg
pd-concepts/                thumbnails of the other concept sites
tools/                      build + audit tooling (never deployed)
```

## Working on it

**Never hand-edit the `*.html` at the repo root.** They are generated. Edit
`tools/content/<page>.html` (the inner `<main>` only) or `tools/chrome.mjs`
(banner, nav, footer, head, icons), then:

```bash
node tools/build-pages.mjs           # regenerate all seven pages
node tools/build-pages.mjs --check   # fail if any page is stale
```

The chrome lives in one place on purpose: the concept disclaimer has to be
identical and correct on all seven pages, and seven hand-maintained copies of
that paragraph is a drift waiting to happen.

### Before pushing

Both of these must pass:

```bash
node tools/shoot.mjs          # 7 viewports x 7 pages: overflow, tap targets, console
node tools/check-motion.mjs   # reveal targets visible in reduce / nojs / normal
```

`shoot.mjs` sweeps **1440, 1024, 768, 414, 390, 360, 320**. Always seven widths,
not two — a previous concept in this network passed a desktop+mobile check while
overflowing by 46px at 320px. 360px is the most common Android width in South
Africa, which is this audience.

> Running the full sweep hammers Google Fonts with ~49 rapid loads and can
> produce transient 404 console warnings on the last viewport. Re-check a single
> page before believing them.

### Assets

```bash
node tools/find-images.mjs --all     # download ~130 Pexels candidates
node tools/contact-sheet.mjs         # lay them out as reviewable grids
node tools/fetch-assets.mjs          # fetch the PINNED winners into assets/
node tools/contact-sheet.mjs --assets # review what actually shipped
```

Look at every candidate. Search-result `alt` text is empty, and two picks that
looked fine as thumbnails were wrong at full size (see `CONTENT-NOTES.md`).
`fetch-assets.mjs` warns on anything over 400 KB and falls back to a slug lookup
when the canonical CDN path 404s.

## Things worth knowing before you change them

- **`img[width][height]` scores (0,2,1).** Any selector that makes an image fill
  its frame must repeat those attributes or it silently loses and the image
  collapses to intrinsic height. There is a list at the top of `styles.css`.
- **`.nav-links a` beats `.nav-call`.** A descendant selector at (0,1,1)
  out-ranks a component class at (0,1,0); the phone button is scoped as
  `.nav-links a.nav-call` for exactly this reason.
- **The zone finder and the bulk calculator read their data out of the DOM**,
  not from arrays in `site.js`. The crawlable table is the whole point of the
  rebuild, so it has to exist in HTML regardless — a second copy in JavaScript
  would drift the first time a fee changed.
- **Grid item counts are designed for.** `auto-fit` does not know there are six
  cards; `.segs` and `.cards-3up` raise their `minmax` floor to force three
  columns so six items break 3+3 instead of 4+2.
- **Reduced motion forces reveal targets back to `opacity: 1`.** Killing the
  transition alone leaves them stuck hidden, which blanks the page for the users
  least able to work around it. `check-motion.mjs` asserts this.
- **Nothing sends anywhere.** Both forms say so *above* the fields, not after
  submission — a visitor should know before typing an address into it.
